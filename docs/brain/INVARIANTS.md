# Invariants & Locked Decisions

Laws every change must respect. Present tense, no dates, no branch names. When a decision changes, edit the line — don't append a contradiction.

## Fee math (canonical: `lib/mediaplan/burstAmounts.ts::computeBurstAmounts`)

```
budgetIncludesFees:      fee = budget × pct/100          media = budget × (100−pct)/100
clientPaysForMedia:      fee = budget/(100−pct) × pct    mediaAmount = 0, deliveryMediaAmount = budget
standard (net budget):   fee = budget × pct/(100−pct)
bonus / package_inclusions: all zeros
pct === 100 → fee = 0 (division guard)
```

- Fee is a **slice of gross**, never `net × fee%` stacked on net (the legacy anti-pattern).
- Container `get*Bursts` helpers and `useMediaChannelContainer` pass `buyType` into `computeBurstAmounts` so UI rollups match finance for bonus / package_inclusions.
- Expert-grid Apply must not restore a bonus / package_inclusions card's previous cost: `attachBurstPreserve` passes the generated line's `buyType` into `preservePreviousBurstsIfApplyWouldZeroBudget`.
- An explicit `"0"` on a non-production burst is **stated money**. `buildEditorLineItemInputs` and `buildSavePlanLineItemsFromSnapshots` back-fill `enteredAmount` from the line total only when every raw burst has `parseMoneyInput(budget) == null` (never entered). Production stays on the mapped-sum `<= 0` path because its budget often lives in `cost`×`amount` with a blank `budget` key.
- `buyType` match is case-insensitive and trimmed (`"Bonus"` / `" bonus "` → zero).
- Production channel null/blank `buyType` resolves to `"production"` at `resolveBuyTypeForChannel` (`buildEditorLineItemInputs` and production form hydrate). Stored `line_items.buy_type` is not rewritten.
- Never round fee% before applying to gross. Never sum net media and apply fee% once at channel level.
- Rounding order: full float per burst → round at burst level (AUD 2dp) → sum rounded burst fees for campaign totals.
- All fee rates are 0–100 percent points, never 0–1. Missing/null → 0 at compute boundaries.
- Publisher forecast `*_comms` are unconditional whole-percent after the AA take: retained = `max(0, rate − 2)` via `retainedCommissionRate` / `applyForecastCommissionRate` (AA takes 2% of gross media, fixed). Values in (0, 1] are a data error — log `[forecast-commission-scale]` once (never block / never reinterpret as decimal fraction). Rate below AA clamps to 0 and logs `[retained-commission-zero-aa]` (rate 0 = not set); never negative revenue. Client-pays lines earn $0 commission.
- Client fee columns map 1:1 to channels; Influencers = `feeinfluencers ?? feecontentcreator`; integration has NO fallback; production fee is always 0.
- **`client_pays_for_media` is a media gate only** — agency fees always flow to the agency invoice. Media rollup keeps `effectiveBudget = 0`; fee proration does not. A receivable must never include a client-pays **media** component: `derivePlanReceivableBillingRecordsForMonth` drops a media row when the schedule item is flagged **or** the joined plan line (`version_id` + `line_item_id`, dual-shape) has `client_pays_for_media`, and logs `[finance-derive]`; the Assembled fee on that month stays. Record `total` stays the schedule-month header (`monthExGstFromScheduleEntry`), not a re-sum of remaining lines.
- When the client pays media direct, Assembled still invoices the service fee, always. Media contributes 0 to billing and receivables; the fee contributes in full. Client-paid media never appears in MBA gross media (explode already excludes it; keep that).
- **Receivable `status` is campaign status.** `derivePlanReceivableBillingRecordsForMonth` binds `resolveFinanceCampaignStatus` once per version and maps `booked`/`approved`/`completed` → record `booked`, else `draft`. Never a bare `status` identifier (that is `Window.status`).
- Fee seed idempotency is **by value** (skip when equal within $0.01), not by-defined. Agency-fee month-total drift tolerance = **$0.01** (modal save + everywhere else).

## bursts_json contract (`lib/mediaplan/serializeBurstsJson.ts`)

- Money fields are **formatted strings** (`mediaAmount`, `feeAmount`).
- `mediaAmount` = *planned* media, sourced from `deliveryMediaAmount` → non-zero for client-pays lines.
- Persist path passes line `buy_type`/`buyType` into `serializeBurstsJson` → `computeBurstAmounts`, so `bonus` / `package_inclusions` always write zero media/fee.
- Expert Apply `preservePreviousBurstsIfApplyWouldZeroBudget` does **not** restore previous bursts when the **generated** line's buy type is `bonus` / `package_inclusions` — generated zero is the intended budget. Every other buy type still refuses Apply that would wipe a non-zero card total. Match is case-insensitive and trimmed (same as fee math).
- `lib/pacing/burst/parseBursts.ts` key names are contractually aligned with the serializer — change both or neither.
- Expert grids' `sumFee` reads `expertRowFeeSplit` output, NOT `bursts_json[].fee` — orthogonal paths that look identical.
- Burst money as `z.number()` vs string: `baseBurstShape` in `lib/mediaplan/schemas.ts` is extended by every channel schema — a type change there fans out to all of them.

## Campaign budget remaining (create + edit wizard)

- Campaign budget means **total investment including fees** = `mbaScopeTotals.nettExGst` = grossMedia + fee + adServing + production, ex GST.
- `mbaScopeTotals.grossMedia` excludes production lines (`scheduleMediaType` / perLine `mediaType`); production is only the `production` component — never both, or nettExGst double-counts it.
- DRAFT SUMMARY “Budget remaining” = `campaignBudget − nettExGst` on **both** create and edit (`lib/mediaplan/campaignBudgetRemaining.ts`). Never subtract media-only (`grossMedia`).
- Overspend is strict `< 0` on the cent-rounded remaining — no dollar-band tolerance to hide true fee/rounding composition.

## Pacing law

- **ZERO-$ LAW:** CM360 surfaces carry no spend UNLESS the line's `delivery_source_map` row sets `derive_spend_from_plan`, in which case the figure is modelled from the plan rate, capped at the planned total, and labelled as modelled. The flag is OFF for all Direct Booked Digital, so `lib/pacing/ad-serving/*` and `lib/pacing/overview/mapOverviewItems.ts` keep their no-spend row shapes (`budget`/`spendToDate` null; status `serving | no-data` only). Delivery `ChannelKey` for this family is `digital-display` | `digital-video` | `digital-audio` | `bvod` (there is no `ad-serving` ChannelKey). Delivery snapshot `group` strings are `digital_display` | `digital_video` | `digital_audio` | `bvod` (not `ad_serving`). Finance `monthEntry.ad_serving` is a per-line cost field, not a delivery group. - Direct Booked Digital renders four containers by media type (Digital Display, Digital Video, Digital Audio, BVOD); all four read PACING_FACT channel 'Ad Serving - CM360' and are partitioned by plan container.

## UI / design system

- Application roles are `admin` | `client` only (`lib/rbac.ts`). Unknown or removed role strings (including legacy `manager`) normalise to no roles — least privilege, never admin.
- List surfaces map fetch + filter outcomes through `lib/ui/viewState.ts` (`ViewState` / `resolveListViewState` / `viewStateFromReadResult`) and render via `ViewStateBoundary` — loading, error, empty, and filtered-empty are mutually exclusive; never render an empty-state message for a failed load or a "nothing here" copy when filters excluded everything.
- `lib/data` Postgres (and live) reads must not catch-and-return `[]` on failure — typed `ReadResult` / throw, then ViewState error at the boundary. Cache freshness (`x-cache-fetched-at` / stale warning) is optional `ViewState.ready.freshness` (derived). Xano `fetchAllXanoPages*` soft paths are dying-at-T6 — see `docs/brain/READ-FAILURE-REGISTER.md`.
- **Fail-soft must be distinguishable from success.** If a handler degrades to an empty or zero result rather than erroring, it must signal that degradation in a way the **caller actually reads** — not only a response header or log nobody consumes. A caller that cannot tell "empty" from "broken" must treat empty as broken. Pattern that has bitten repeatedly: optional dependency → benign default → total failure renders as a healthy zero/empty. Instances: `getRateForMediaType ?? (() => 0)` (ad-serving); `catch → return []` (data readers); empty-state-instead-of-error (list UI); `$0.00` for a whole cost category; `row.weeklyValues[sundayKey]` → `undefined` → silently skipped. Live instance: `GET /api/clients` returns `200 []` + `x-warning: clients-unavailable`. Shared helper `lib/clients/fetchClientsList.ts` refuses that shape as success (`clients-unavailable` on empty = failure; `served-stale-after-upstream-failure` on non-empty = degraded ok). Wrong-action consumers (#1–4, #13–14) converted; blank-ui filters (#5–12) and AppSidebar still open — inventory `docs/brain/fail-soft-consumers.md`.

Two drafts in one client-month are Differs with both listed. VOIDED/DELETED ignored. Do not reuse PC6 `matcher/threeTier.ts`.
- Xero → Postgres sync (`/api/cron/xero-sync`) is additive/parity-only until T6: it must not disable Xano `daily_xero_sync`, must upsert only `xero:*` `invoice_key` rows, and must not migrate legacy Xano-hosted PDF blobs (re-fetch from Xero into Vercel Blob). PDF pending is `pdf_file IS NULL OR NOT (pdf_file ? 'url')` — the Xano stub is non-null and has no `url` key; never treat it as attached. A single PDF miss must not fail `sync_pdfs`. The `xero_sync_log` INSERT is fail-open: a completed run still returns its stage result if the log write throws.
- **App writes to `finance_billing_records` key on `invoice_key` and never touch `xero:` rows.** Notes, PATCH-by-id, line-item mutate, approve, unapprove, mark-exported, and Xero match stamps go through `lib/data/writeFinance.ts` (Postgres). Mark-billed is retired (`POST /api/finance/billing/mark-billed` returns 410). PATCH-by-id is field-allowlisted: `notes`, `po_number`, `payment_days`, `payment_terms`, `status`, `invoice_date`, `campaign_name`. Any other body field — including `total`, `billed`, `billed_at`, `billed_by`, `billed_amount_cents`, `billed_lines_hash`, and every `approved_*` / `exported_*` / `matched_*` column — returns `FIELD_NOT_ALLOWED` naming the field. Line-item `amount` / `received_amount` stay editable until the parent is approved; **delete** is money-bearing and uses the same SQL freeze (`r.approved_at IS NULL` on a `USING finance_billing_records` join, sibling of the PATCH path). `APPROVED_FROZEN` after a zero-row DELETE is classified from the parent stamp — the guard is the predicate, not a read-then-delete. Unapprove and mark-exported return `ok: errors.length === 0` (`boolean`); per-key failures are not `ok: true`. `setFinanceBillingRecordXeroMatch` writes only `matched_xero_invoice_id` / `matched_at` / `matched_by` — never `approved_*`. Xero import keeps the inverse `WHERE invoice_key LIKE 'xero:%'` guard. The two writers must not share a key. Queue `assign_client` is the Xero-path exception (`lib/xero/contactLinks.ts` stamps `clients_id` on the `xero:` row in the same txn as the contact link) — not `writeFinance`.
- **Client billing lifecycle state is derived from evidence stamps on `finance_billing_records`, never a stored `state` column.** Derivation is `lib/finance/billingLifecycle.ts` (`resolveBillingState`) in this order: live Xero PAID / amountDue ≤ 0 / fullyPaidDate → `paid`; AUTHORISED past due with amount due → `overdue`; AUTHORISED → `issued`; DRAFT → `drafted`; VOIDED/DELETED treated as no Xero; then `exported_at` → `sent_to_finance`; `approved_at` → `approved`; else `ready`. Dates compare as Australia/Sydney civil days (`sydneyCivilParts` / `sydneyYmdFromUtcInstant`). Invoicing UI renders `BillingStateBadge`; the mark-billed toggle is gone. `POST /api/finance/billing/mark-billed` stays callable and returns 410. Approve is the only human lifecycle transition (`POST /api/finance/billing/approve`, bulk `invoice_keys` + per-key grains for materialise/snapshot). `reapprove: true` overwrites the snapshot only while `exported_at` is null; once sent to finance, re-approve refuses 409 (`ALREADY_EXPORTED`), matching unapprove — "sent to finance" freezes the approved amount. Amend by un-marking sent, re-approving, then re-marking sent. A re-approve audit `old_value` is JSON of the prior `approved_at` and `approved_amount_cents`. Any finance admin may approve — attribution (`approved_by` / `approved_by_name`), not routing; no account-lead field. Unapprove (`POST /api/finance/billing/unapprove`) clears the approval stamp and snapshot, refuses once `exported_at` is set, resolves keys first, transacts only the resolvable ones, and returns the rest as per-key errors. Approve `ALREADY_APPROVED` is the same shape (per-key on 200). `POST /api/finance/billing/mark-exported` stamps approved keys, returns skipped unapproved keys, and returns missing keys as per-key errors — it does not silently succeed on zero stamps. App writers do not set `billed` / `billed_at` / `billed_by` — PATCH-by-id refuses those fields (`FIELD_NOT_ALLOWED`); the 410 mark-billed route is the retired human writer. `billed_amount_cents` / `billed_lines_hash` stay for billed-era drift; approval snapshots use `approved_amount_cents` / `approved_lines_hash` hashed with the same `hashBilledLineSet`. Overlay reuses `detectBilledDrift` against the approval snapshot (`approved_drift` on the badge as "Approved · changed since"; does not block). Stamps: approval (`approved_at` / `approved_by` / `approved_by_name` + `approved_amount_cents` / `approved_lines_hash`), export (`exported_at` / `exported_by`), Xero match (`matched_xero_invoice_id` / `matched_at` / `matched_by` = `auto`\|`manual`). `matched_xero_invoice_id` is `xero_ar_invoices.xero_invoice_id` as text with no FK.
