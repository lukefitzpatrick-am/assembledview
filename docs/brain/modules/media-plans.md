# Module: Media Plans

The campaign builder. Creates an MBA-numbered plan (`media_plan_master`), cuts immutable version rows (`media_plan_versions`) per save, and writes per-channel line items into 20 Xano tables (`media_plan_television` … `media_plan_influencers`), each row carrying a `bursts_json` array. Generates the MBA PDF + media plan Excel and uploads them to the version row.

## Save protocol (verified)

**Xano path (current default, `WRITE_BACKEND=xano`):**

1. Compute `approvalSelectionFingerprint`; approval-set change → `forceIncrement`.
2. `PUT` with `deferMasterVersionPublish: true` → server: reap staged orphans → `nextMbaVersionNumber` → `recomputeAndValidateBillingScheduleOnSave` (authoritative; 409 on $0.01 divergence) → POST new version row (or PATCH in place while `status === "draft"` && !forceIncrement).
3. ~20 conditional per-channel `save*LineItems` writes. Any failure → abort, master NOT advanced.
4. Docs generated + uploaded in parallel. **Below approved** (draft/planned): MBA PDF + Media Plan file steps are marked `skipped` with “Documents generate from approved versions” (`lib/docs/saveDocSteps.ts`); SavingModal does not enter “Saving with Errors” for skips alone. PC3’s approved-or-beyond gate on `/api/mba/generate` stays; only the dialog classification changed. Real doc failures on approved+ remain `error`.
5. `PATCH` publish (advance `master.version_number`). Failure → Retry-publish button. Xano has no multi-table transactions — stage-then-publish is the closest contract; abandoned failures leave staged rows until the next save reaps them.

**Postgres path (`WRITE_BACKEND=postgres`, T4c wired):** `POST /api/plans/save` → `savePlanVersion` then best-effort `mirrorPlanToXano` — draft updates `(master_id, version_number)` in place; `new_version`/`publish` insert at server-resolved tip+1 (O4.6; client `versionNumber` ignored for those modes); line ids are client-stable (never regenerated); publish aborts if `count(line_items)=0` (BOSS006); mid-txn failure rolls back version + lines + schedules (PENFOLD016 kill-shot). Editor sends `masterId` from `media_plan_master_id` (not combined-payload version `id`); mismatch vs mba → 422 `MASTER_ID_MISMATCH` (no silent remap). Publish carries mapped `campaignStatus` (lowercase: draft/planned/approved/booked/completed/cancelled) — no `"Approved"` invent. 23505 on versions UNIQUE → `VERSION_ALREADY_EXISTS` (not line-id dupe) — backstop only once tip is server-resolved. Mirror failure leaves Postgres intact and returns `{ mirror: "failed" }` (retry via admin); publish mirror also PATCHes Xano master watermark. Create/edit SavingModal steps collapse to transactional save → mirror → KPI sync. **O4:** AUTO-line / month-header drift vs the burst `autoReference` preview does **not** pre-block save (server recomputes `schedule_months` + blob anyway); response may include `billingCorrection` for a visible toast. Explicit `billingMode=manual` + C2 sum violations still 409. Xano MBA PUT still uses `recomputeAndValidate` reject-on-AUTO-divergence until T6. **O4.5:** create/edit postgres bodies go through `assemblePlansSaveRequestBody` — `feeLoading` / `feeSnapshot` / `adservaudio` always ride the shared assembler (no per-branch fee wiring). `buildSavePlanLineItemsFromSnapshots` prefers stamped snapshot `feePct` over billing-input meta. `savePlanVersion` logs `[savePlan-fee-zero]` (never blocks) when any line resolves a non-zero feePct but `mbaScopeTotals.fee` is $0. **Stage 2b / PC7:** save on a published tip writes `plan_working_drafts` (not a version); matching-base drafts auto-apply after hydration (stale-base keeps Load anyway — never silent overlay of a newer tip); Compare stays available; Discard / successful save clear the draft via `deleteWorkingDraft`. Autosave chrome remains flag-gated (`NEXT_PUBLIC_PLAN_DRAFTS`); persistence + offer are always on.

## Load

Header via `GET …?skipLineItems=true&billingScheduleFull=1&version=N`, then per-channel line items (60s soft cache + in-flight dedupe). `channelHydrationGate.computeAllChannelsHydrated` gates Save until every enabled container settles. Channel GETs are FK-first (`fetchChannelLineItemsByMba`) with a 5-attempt param-shape fallback for legacy rows. Edit-page `mba_line_approvals` hydrate uses `fetchMbaLineApprovalsClient` → `coalescedGetJson` (30s TTL); effect deps on `billingFeeSeedEnabledConfigs` can re-enter, but same-URL callers share one GET; save/approval PATCH invalidates. Browser media-details reference GETs (`getMagazines` / `getMagazinesAdSizes` / `getDisplaySites` / …) go through `fetchMediaDetailBrowser` (24h TTL); MagazinesContainer and DigitalDisplayContainer mount effects no longer double-hit the network under remount churn.

Edit-page channel-load budgets (Xano fan-out): **45s** initial + **90s** auto-retry; manual retry **180s**; hydration watchdog **150s** (must exceed initial+auto-retry). Late success after the watchdog still applies data and clears that channel's error/`did not finish loading` toast via `mediaLoadStatusAfterChannelSuccess` / `lineItemLoadToastAfterChannelSuccess`, **except** after Resume has restored a working draft — those tip `setter()` writes are ignored so they cannot clobber draft bursts. The channel still settles (`ready`) so Save is not stuck on Loading.

Empty API payloads settle immediately in the loader; non-empty channels settle when the container publishes via `onMediaLineItemsChange`. `LazyMountWhenVisible` force-mounts once that channel's `mediaLoadStatus` is `ready`/`error` (not only when global `loadPhase === "ready"`), so off-screen Search/etc. still settle. Loader effect cleanup clears `lastLineItemsLoadKeyRef` but does not bump the load generation — a 200 that arrives after cleanup still applies (P1-AMEND late success); only a newer load generation discards results.

## Gotchas (verified)

- Create vs edit mega-pages duplicate xlsx/pdf generation, publisher fetch, MBA numbering, ~20-branch save blocks. Create reads `fv.mp_client_name`; edit reads `fv.mp_clientname`. Doc-step skip/error classification on save must stay twin-synced (create + edit).
