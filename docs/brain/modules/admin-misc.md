## Admin & users

- `app/api/admin/users/route.ts` — `requireAdmin` → Auth0 Management API. **GET** lists users (`listAllAuth0Users`, 60s in-process TTL cache) returning denormalised `app_metadata.role` (can drift from Auth0 RBAC — not authoritative). **POST** creates user → assign role by **Role ID** `rol_…` from `AUTH0_ROLE_ADMIN_ID`/`AUTH0_ROLE_CLIENT_ID` → password ticket → invite email (rolls back on failure). **PUT** updates metadata/role. Rejects numeric `clientSlug` (historical bug guard). Creating/promoting to `admin` requires `SUPERADMIN_EMAIL_ALLOWLIST` (`lib/auth/canGrantAdminRole.ts` / `assertCanGrantAdminRole`) — fail closed when unset; not a third app role.
- `app/admin/users/page.tsx` — admin users table (server-paginated GET, Auth0 `query` search). Wrapped in client `AdminGuard` (redirect only — real gate is `requireAdmin` on the API). Uses `ViewStateBoundary` so fetch failures render as error, not empty.
- `app/admin/users/new` — invite form; Admin role option hidden when session email is not allowlisted (cosmetic; API enforces).
- `app/admin/m365-reconciliation` — read-only M365 identity reconciliation skeleton (M4). `GET /api/admin/m365-reconciliation` → `requireAdmin` → pure join in `lib/m365/reconciliation.ts`. See [`modules/m365.md`](./m365.md).
- `app/admin/myhours-mapping` — unmapped mirrored MyHours time for the current Sydney week; one-click assign writes `mapping_source='manual'` via `GET|POST /api/admin/myhours-mapping`. Schema: `0028_myhours_time.sql` (+ `0031` unknown_user_count, `0032` time-entry proposals) / `db/schema/myhours.ts`. Cron `GET/POST /api/cron/myhours-sync` (`MYHOURS_API_KEY` + `CRON_SECRET`) ensures client projects + campaign tasks, pulls `Reports/activity` (date-chunked; Users join for email), upserts `time_entries`. Campaign hours widget + Codex team-week hours read `time_entries` through `/api/codex/time/*` (Codex shadow gate — never client roles). Fireflies time proposals live on `/tasks` Team; only `POST /api/codex/time/proposals/[id]/confirm` writes a MyHours log, and blocked-structure rows link here for manual mapping.
- `app/admin/fireflies-unattributed` — nav label **Fireflies meetings**. Tabs All | Clients | Publishers | Internal | New Business | Unattributed (default Unattributed). Same table + grouped Assign dropdown on every row (reassign allowed). Assign is row-scoped (one `note_id`); learning still upserts domains/title rules and never deletes prior learning; matching other unattributed notes are counted in `would_reattribute` only (not written). Clients tab shows attributed `mp_client_name`. Title click expands the stored summary. Client Hub Meetings (`ClientMeetingsSection` on `/client/[slug]`) is read-only `client_notes` where `client_id` = this client via `GET /api/clients/[id]/meetings` (`requireAdmin`); badge when the note auto-created tasks. Publisher Hub Meetings remains `publisher_id` + `attributed_type='publisher'`. **Sync now** (`POST /api/admin/fireflies-sync`, `requireAdmin`) runs the same pull as cron. Cron `GET/POST /api/cron/fireflies-sync` (`FIREFLIES_API_KEY` + `CRON_SECRET`) pulls transcripts into `client_notes` and advances `fireflies_sync_state` cursor. Attribution is client-name-in-title first, then client domain, then publisher domain, then title rules, then roster-internal; MBA is a client-only refinement. Human accept lives on `/tasks` Inbox.
- `app/account` has no Team tab — admins reach user management via `/admin/users` (routeManifest label). Do not reintroduce a mock roster.
- `app/admin/**` uses client-side `AdminGuard`; server enforcement lives only in the API routes.
- Access-denied UI is one shared `components/AccessDenied.tsx` (`reason`: permission / unconfigured / unauthorized). Routes `/403`, `/forbidden`, `/unauthorized` stay as thin wrappers — middleware fail-closed redirects target them; do not delete the routes.
- Sidebar logo and breadcrumb root link to `/dashboard` (in-app landing), not marketing `/`.
- `app/(internal)/**` (chart gallery) is gated by `app/(internal)/layout.tsx` — `notFound()` when `NODE_ENV === "production"`.
- `publisher_profiles` (`0024` + `0033` SEN seed / `0034` money map / `0035` SCA `reference:ignore` / `0036` nullable `publisher_id` FK to `publishers.id` with explicit four-row backfill / `0037` ingest_runs / `0038` SCA drop `Days` / `0049` `line_granularity` default `per_row` / `0050` ingest_stages (staged `IngestReviewPackage` jsonb; retain on accept) / `db/schema/publisherProfiles.ts`) holds ingest mapping as jsonb config (column_map, legend_map, sheet_rules, grid_semantics, line_granularity). ## Knowledge hub (`src/**`)

- `src/lib/learning/` — Fuse.js search (`searchTerms` exact-matches term/alias before fuzzy), formula solver/evaluator, UTM builder, `termLinks.ts` (home search + guide related-term hrefs land on the correct section for the term type). `src/data/learning/terms.json` (467KB) is **generated** by `npm run build:learning` from `terms.raw.csv` — formula DSLs live in `KNOWN_FORMULAS` inside `scripts/build-learning-terms.ts` (edit there, then rebuild); do not invent expressions only in the JSON.
- `solveForVariable` inverts via bracketed bisection on a geometric probe ladder (adjacent defined probes only; root verified against the residual). Power-law/monomial fit is gone — margin and ratio formulas reverse-solve correctly. Percent display goes through `formatPercent(..., { decimals: 2 })` so calculator output stays `"40.00%"`.
- Percent calculators multiply by 100 in the expression (not in `formatValue`); currency display uses en-AU/`formatMoney`. Evaluator throws a named error if any non-numeric token remains after substitution.
- Calculator cards (`FormulaCalculator`) auto-calc on input change — no Calculate button; result is `readOnly` (selectable) with a copy control.
- `app/knowledge/layout.tsx` — shared sub-nav across Overview / Glossary / Acronyms / Formulas / Calculators / Guides / Platforms / Resources / UTM Builder.
- Consumers: `app/knowledge/**` + `components/learning/*`. Nothing else imports `src/**` except `src/ava` (AVA prompt primitives).
- The `src/` vs `lib/` split is historical, not architectural — same `@/` alias, no boundary.
