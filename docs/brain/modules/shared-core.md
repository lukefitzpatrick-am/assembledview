# Module: Shared Core

The server-side data-access + identity layer everything sits on: Xano URL/auth construction, payload normalisation, pagination, Auth0 session + RBAC, caches, formatters, middleware, build config.

## Xano layer

- **`lib/api/xano.ts` (106 importers)** — single choke point: `getXanoBaseUrl`/`xanoUrl` (env fallback chains), `xanoAuthHeader*` (`Bearer $XANO_API_KEY`, server-only), `parseXanoListPayload` (normalises 4+ response shapes; returns `[]` silently on unknown shapes).
- `lib/api/xanoPagination.ts` — `fetchAllXanoPages` (dual pagination styles, dedupe, silently caps at 10,000 rows; `WithCompleteness` marks `complete=false` on unsupported-pagination early-stop or swallowed non-404 errors; truncates wrapped envelopes — DI-5).
- `lib/api.ts` (3.9k-line monolith) — ~150 channel CRUD functions; isomorphic: server hits Xano direct, browser rewrites to `/api/*` proxies. **Throws at import server-side** if publisher/client base URLs unset; imported by client components → no Node-only deps allowed.
- Two catch-all proxies (`/api/media_plans/[...path]`, `/api/media-details/[...path]`) gated by `lib/security/proxyAllowlist.ts` (path depth ≤2, numeric second segment, per-path method sets) **and** `requireRole(["admin"])` on every method (SEC-1 / SEC-D Constrained, PS-1 live-verified — dies with Xano reads at T6). Temporary soak telemetry: every staff-gate 403 logs `[proxy-403] path=… role=… userId=…` via `lib/security/logProxy403.ts` (remove in X6 if silent).
- **`lib/data/toApiRow.ts`** — shared Drizzle→API shaping (`toApiRow` camel→snake + `coerceNumericStringsToNumbers`). Drizzle `numeric` strings become numbers to match Xano; **`IDENTIFIER_TEXT_FIELDS`** (`mba_number`, `po_number`, `abn`, `postcode`, `invoice_number`, `invoice_key`, `client_contact`, `mbaidentifier`, `line_item_id`, `mp_plannumber`) never coerce — API contract: `mba_number` is always a string, byte-identical to Xano. Callers may union extra `keepAsText` keys (clients still pass `abn`).
- **`lib/search/matchText.ts`** — shared tolerant search primitive (case/diacritic/whitespace-normalised, multi-token AND + token-prefix, `String(x ?? "")` everywhere). List/filter surfaces route free-text search through `matchText` / `matchTextAny`; fail-closed access scopes (pacing `client_ids`) only reuse `normalizeSearchText` for exact-key equality. No Levenshtein ranking yet.
- **`lib/data/readResult.ts`** + **`lib/ui/viewState.ts` (`viewStateFromReadResult`)** — M7 adapter: live reads must not soft-fail to `[]`; failures become ViewState error. Register of converted vs dying-at-T6 Xano page wrappers: `docs/brain/READ-FAILURE-REGISTER.md`.
- **`DATA_BACKEND=xano|shadow|postgres`** (default `xano`) — Phase 2 cutover switch. Per-domain override via `DATA_BACKEND_<DOMAIN>` (`REFERENCE`, `PUBLISHERS`, `CLIENTS`, `KPI`, `FINANCE`, `PACING`, `PLANS`, `APPROVALS`) falling back to global `DATA_BACKEND`. Reference-table GETs go through `lib/data/readReferenceMediaDetail.ts`; publishers via `lib/data/readPublishers.ts` (wired in `publishersCache` + server `fetchAllPublishers`); clients via `lib/data/readClients.ts` (wired in `clientsCache`, `fetchClientById`, `/api/clients/[id]`, server `getClientInfo`). **Client writes (X1):** `lib/data/writeClients.ts` — PG first + fire-and-report Xano mirror (`xano_client_mirror_failed`); invalidates both `clientsCache` and `xanoReferenceCache`. Clients include social URL + `client_brain` columns (`0004_clients_missing_columns.sql`) — required before any `DATA_BACKEND_CLIENTS=postgres` flip. Seq sync: `0015_clients_id_seq_sync.sql` (author-only) + runtime `syncClientsIdSequence` before insert. **Reference writes (X4):** `writePublishers` / `writeReferenceMediaDetail` / `writeMediaContainerBestPractice` — PG first + Xano mirror (`xano_publisher_mirror_failed` / `xano_reference_mirror_failed` / `xano_media_container_bp_mirror_failed`); bust `publishersCache` + `xanoReferenceCache` publishers + `mediaContainerBestPracticeCache`; browser media-details 24h TTL still busted by `lib/api.ts` create* helpers. KPI via `lib/data/readKpi.ts` (wired in `lib/kpi/{campaign,client,publisher}Kpi.ts` GETs, `publisherKpiCache`, `lib/xano/campaignKpi.ts` pacing bulk); campaign/client KPI writes PG-first via `writeKpi` (X5 mirror). Finance via `lib/data/readFinance.ts`. Finance schedule derive source is separate: `DATA_BACKEND_FINANCE_SCHEDULE=blob|shadow|rows` (default `blob`) in `lib/finance/scheduleMonthsSource.ts`. Pacing via `lib/data/readPacing.ts` (masters + versions crawl in `fetchAllMasters` / `fetchCurrentVersionRowsForMasters`, `pacing_orphan_fixes` list; null `published_version_id` masters resolve `version_number` as `COALESCE(published, max(vn), 0)`). Plans via `lib/data/readMediaPlans.ts` (masters/versions with `legacy_schedules` blob passthrough; per-channel line items reassembled from consolidated `line_items` — attrs spread + `bursts`/`bursts_json`; wired in `fetchChannelLineItemsForMbaGet`, media_plans catch-all, `mediaPlansListCache` / `mediaPlanVersionsCache`, `getMediaPlanVersions` / by-MBA helpers). Plans postgres also serves finance-hub treemap feeds via `lib/data/dashboardMonthlySpend.ts` (wired in `lib/api/dashboard/global.ts`; xano/shadow keep Xano `dashboard_monthly_*`). `XANO_LINE_ITEMS_SNAPSHOT` cron stays Xano until T6. **`DATA_BACKEND_PLAN_DETAIL=xano|postgres`** (default `xano`) gates only `GET /api/mediaplans/mba/[mba_number]` — intentionally does **not** fall back to global `DATA_BACKEND` (C-22 soak). `postgres` → `lib/data/readMbaPlanDetail.ts` (one query set; 500 `PLAN_DETAIL_POSTGRES_FAILED` on error, no Xano fallback). ### Env vars (traps)

- Alias pairs both live: `XANO_MEDIA_PLANS_BASE_URL` / `XANO_MEDIAPLANS_BASE_URL`. Fallback chain order matters.
- `XANO_BASE_URL` triples as generic fallback AND the assistant endpoint — setting it wrong silently mis-routes clients/media-plans calls.
- `DATA_BACKEND` (`xano` \| `shadow` \| `postgres`, default `xano`) — unknown values fall back to `xano`. Per-domain `DATA_BACKEND_<DOMAIN>` overrides when set. `postgres`/`shadow` need `DATABASE_URL`. Shadow diffs are in-memory per process (not durable across cold starts).
- `DATA_BACKEND_PLAN_DETAIL` (`xano` \| `postgres`, default `postgres`) — MBA combined-detail GET only; does not inherit global `DATA_BACKEND`. Postgres is the only implemented branch; `xano` → 410 (`PLAN_DETAIL_XANO_GONE`).
- Missing `XANO_API_KEY` → **no auth header, no error** (only `requireXanoAuthHeaderRecord` throws). `getRequiredEnv` returns `""` in the browser.
- Module-scope throws (boot failures, not 500s): `lib/auth0.ts`, `lib/api/auth0Management.ts`, `lib/api.ts:17-18`, admin users route.
- `http://localhost:3000` fallbacks reachable in prod if `NEXT_PUBLIC_BASE_URL`/`AUTH0_BASE_URL` unset: `internalBaseUrl.ts`, `frameSign.ts`, `lib/utils/auth.ts`, account page.
- Several `XANO_TIMEOUT_MS`-named constants are hardcoded locals, not env reads.
- README's Xano config section is stale (references nonexistent `lib/xano/config.ts` and unused env names).

## Auth (Auth0 v4)

- `lib/auth0.ts` — singleton; throws at import on missing env (app-wide outage). `beforeSessionSaved` persists namespaced custom claims (dual-domain `.com`/`.com.au` + env-overridable).
- `lib/rbac.ts` (53 importers, edge-safe) — roles admin/client (`manager` removed 31 Jul 2026 pending a real definition); 4-tier resolution (namespaced claim → app_metadata → user_metadata → admin-only permission inference); unknown/removed role strings fail closed to no roles (never admin); numeric-only client slugs rejected; role-less valid session = authenticated but every requireRole 403s and middleware blocks staff surfaces (Auth0 Post-Login Action must be enabled).
- `middleware.ts` — Auth0 session roll → `/api/*` 401 JSON if no session; pages redirect to login; client-role users confined to `/dashboard/{their-slug}`; sessions with no recognised role go to `/unauthorized` (fail closed). **Authentication only — tenant isolation is per-handler** (SEC-8). Bypasses: `/auth/*`, `/api/auth/*`, **`/api/cron/*`** (only `assertCronSecret` protects crons), static.
- Gates: `requireAdmin`, `requireFinanceAdmin` (all finance routes), `requireRole(["admin"])`, `checkClientMbaAccess` / `resolveClientMbaScope` (bulk + per-channel pacing POSTs, campaign KPI GET, MBA/creative/delivery, mediaplans list filter, **campaigns/[mba_number]** GET + billing-schedule — O6; fallback uses `mbaNumberMatchesClientIdentifier` — SEC-9 FIXED). **SEC-G:** only `admin` is unscoped inside `resolveClientMbaScope`; empty `mba_numbers` on non-admin → 403. Publishers/best-practice writes + television `[id]` mutate + dedicated channel collection POSTs → `requireRole(admin)`; `clients/[id]` GET keeps intentional admin/own-id split. Dynamic `[id]` vs collection inventory: `docs/brain/API-DYNAMIC-ROUTE-GATES.md` (SEC-10 static complete — live probe pending).
- `lib/auth/getCurrentUser.ts` — audit identity; numeric id is always 0 (no Xano users table); identity lives in `*_name` fields.
- Known: two Auth0 client instances exist (`lib/utils/auth.ts` vs `lib/auth0.ts`) — unresolved which new helpers should use.

## Caching (three mechanisms, all per-lambda unless noted)

1. **Coalesced module TTL caches** — clientsCache (10min, invalidated on client writes), mediaPlanVersionsCache (60s + 30s failure backoff, no invalidation), mediaPlansListCache (60s, none), publishersCache (10min, invalidated on publisher writes X4) / publisherKpiCache (10min, none), mediaContainerBestPracticeCache (10min, invalidated on BP writes; postgres upstream when publishers backend=postgres), **finance/xanoReferenceCache — a SECOND independent clients + publishers cache (30s; both invalidated on matching writes)**. All serve stale-on-failure.
2. **`unstable_cache`** (survives lambdas): pacingRowsCache (4h, tag `pacing-campaigns` — the repo's only `revalidateTag` caller is orphan-assign), globalSpendCache (300s, tag never revalidated), planning metaCache (never revalidated).
3. **Browser**: `coalescedGetJson` (default 60s TTL; optional `parseResponse` for fail-soft shapes; `mbaLineApprovalsClient` uses 30s + PATCH invalidation; media-details reference GETs via `fetchMediaDetailBrowser` use 24h session TTL + create invalidation). Collapses Strict-Mode remounts and parallel same-URL callers.

Boot warming via `instrumentation.ts` → dynamic `instrumentation.node.ts` only when `NEXT_RUNTIME === "nodejs"` — skipped on Vercel unless `WARM_CACHES_ON_BOOT=true` (deliberate: concurrent cold starts would starve Xano). Do not put postgres-touching imports (`lib/cache/clientsCache` → `lib/data/readClients` → `db/index.ts`) directly in `instrumentation.ts`; Edge instrumentation still resolves that graph and breaks `npm run build` (Module not found: crypto/stream). `db/index.ts` is `server-only`; `postgres` is in `serverExternalPackages`. Node/tsx suites that import `db/` (e.g. `npm run test:save-plan`) preload `scripts/test-shims/register-server-only.mjs` (+ CJS require shim) so `import "server-only"` is a no-op outside Next. Background refresh was removed on purpose (serverless suspension caused phantom timeouts) — don't reintroduce fire-and-forget refresh.

## Cross-cutting utils

- `lib/utils.ts` (216 importers) — `cn()`, `theme`, `mediaTypeTheme` (channel colour keys are load-bearing).
- `lib/format/money.ts` — client-facing display: `formatMoney` / `formatMoneyCompact` / `formatPercent` (en-AU AUD; null/NaN → "—"). Legacy `getNumberFormat` / `formatRate` defaults are also en-AU/AUD (not en-US/USD). `formatPercent` uses min=max fraction digits when `decimals` is set (tabular columns). Also keeps editor/serialization helpers `formatAUD`, `roundMoney2/4`, `parseMoneyInput`, plus a legacy `formatMoney` overload when locale/currency/fraction options are passed (bursts_json + MoneyInput). Rounding changes = reconciliation drift everywhere.
- `lib/format/date.ts` — client-facing dates: `formatDateShort` ("1 Apr 2026"), `formatDateLong` ("1 April 2026"), `formatDateRange` (collapses shared year/month); all via `parseDateSafe`, en-AU only; unparseable → "—". Remaining `en-US` month-name calls in `app/scopes-of-work/**` page components (`create` / `[id]/edit`) are display labels (`${monthName} ${year}`), not API routes — en-US and en-AU both yield "July", so leaving them is fine.
- `lib/clients/slug.ts` (24) — slugs ARE tenant identity; `legalsuper → legal_super` override is load-bearing. NOTE: pacing uses a different slugifier (`slugifyPlanClientName`).
- Dates: `lib/dates/parseDateSafe` (LOCAL midnight) vs `parseDateNativeSafe` (UTC midnight) are NOT interchangeable — swapping shifts dates by a day. Three Melbourne-date helper families exist (lib/timezone, lib/dates/melbourne, lib/pacing/maths). Presentation formatting for client dashboards goes through `lib/format/date.ts`.
- Duplicate toast hook with separate state: `components/ui/use-toast` (52 importers) vs `hooks/use-toast` (2).
- `tsconfig`: `strict: false` + `strictNullChecks: true`; three perf test files + WIP `scripts/live-*` / `_s1p1b-*` probes excluded from typecheck (they break `next build` typecheck while untracked).
