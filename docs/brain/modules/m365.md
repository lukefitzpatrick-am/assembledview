# Module: M365 (Microsoft Graph provisioning)

SharePoint site + Teams provisioning for client groups, parked. Builds on M1 client identity (`clients.m365_is_anchor`, `siteUrlForClient`). **The Graph provisioning client (`lib/m365/graphClient.ts`, `provisioningLog*.ts`) was deleted in B18 (D7, 3 Nov 2026):** only tests had called it since 12 Aug. Git history keeps it (last present at `c4d15cd1`). What remains is the read-only reconciliation page and the shared Graph transport. **Flag `NEXT_PUBLIC_M365_PROVISIONING` defaults OFF** and only labels the reconciliation page's Graph check column.

## Entra app registration (Luke — portal)

No app registration exists yet. Create an application (daemon / client-credentials) and grant **application** permissions (admin consent):

| Permission | Why |
|---|---|
| `Sites.ReadWrite.All` | Create / resolve SharePoint sites; create folder paths; upload files |
| `Group.ReadWrite.All` | Create M365 groups that back Teams |
| `Team.Create` | Create Teams from groups / team templates |
| `ChannelMessage.Send` | Post channel messages (kickoff / ops notifications) |

**Credential:** certificate (preferred for prod). Client secret is acceptable only for local/dev mocks — do not ship long-lived secrets as the production auth mode. Record tenant id + client id in Vercel env when ready (`M365_TENANT_ID`, `M365_CLIENT_ID`, cert thumbprint / secret for local only).

## Reconciliation (M4 skeleton)

- Every `clients` row, grouped by `lower(trim(mbaidentifier))` (same model as `resolveClientGroup`).
- Columns: derived `siteUrlForClient`, stored `sharepoint_site_url` / `teams_group_id`, dashboard `slug`, casing anomaly (mixed casings in group or non-lower stored id), Graph check = `pending — provisioning flag off` until credentials + live check.
- Unmatched plans: `media_plan_masters.mba_number` with no client identifier prefix match (live set is the 12 junk MBAs from TI-1 §3a). Never provisionable via identifier join — per-row decision required.
- Read-only: no Graph calls, no DB writes from this surface.

## Behaviour laws

- **All network behind one transport** — unit suites inject a mock; no real Graph/login calls in `npm run test:*`.
- The provisioning rules (flag off throws before any token or Graph call, client-credentials token cache, 429 `Retry-After` and backoff, one log row per attempt, check-then-create `ensureSite` / `ensureFolderPath`) went with `graphClient.ts` in B18. A future provisioning build starts from git history (`c4d15cd1`).
