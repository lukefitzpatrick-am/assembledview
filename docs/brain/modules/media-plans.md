# Module: Media Plans

The campaign builder. Creates an MBA-numbered plan (`media_plan_master`), cuts immutable version rows (`media_plan_versions`) per save, and writes per-channel line items into 20 Xano tables (`media_plan_television` … `media_plan_influencers`), each row carrying a `bursts_json` array. Generates the MBA PDF + media plan Excel and uploads them to the version row.

The channel still settles so Save is not stuck on Loading. `"error"` counts as hydrated (page presents as loaded) but is **not** load success: Save/Publish stay blocked (`channelLoadSucceededFromMediaStatus`) and `buildSavePlanLineItemsFromSnapshots` throws instead of skipping `[]`. Create never GETs line items, so enabled channels are loaded by construction (`channelLoadSucceededWithoutFetch`). Do not fold the failed-load gate into `saveHeldForHydration` (that boolean arms the watchdog).

Empty API payloads settle immediately in the loader; non-empty channels settle when the container publishes via `onMediaLineItemsChange`. `LazyMountWhenVisible` force-mounts once that channel's `mediaLoadStatus` is `ready`/`error` (not only when global `loadPhase === "ready"`), so off-screen Search/etc. still settle. The channel-load toast (`MediaPlanLoadStatusPill`) reads `buildHydrationToastItems` from the same maps as `computeAllChannelsHydrated` (`n of m containers ready`, m = enabled containers — not campaign-details + channels). It dismisses only when `allChannelsHydrated` is true (same moment Save unlocks). After 10s (`HYDRATION_TOAST_HANG_MS`) the header names outstanding containers. Loader effect cleanup clears `lastLineItemsLoadKeyRef` but does not bump the load generation — a 200 that arrives after cleanup still applies (P1-AMEND late success); only a newer load generation discards results.

## Partial MBA (version scope)

One client MBA = one published version. Ticked lines and ticked months travel in `plansSaveBodySchema.mbaScope` and are applied inside `savePlanVersion` in the same transaction as the `approved_slice` freeze and the billing explode. The version stores `mba_scope` (`{ lineItemIds, monthYears, partial }`; SQL null = full / pre-scope). New versions do not write `mba_line_approvals`. “Send more” is Publish next version with a wider scope.

Three former stores, which is authoritative now:

| Store | Role now |
|---|---|
| `media_plan_versions.mba_scope` | Authoritative for new saves. Null ids = all lines / all months in. |
| `media_plan_versions.approved_slice` | Frozen billing law at publish. Never mutated afterwards. |
| `mba_line_approvals` | Read-only legacy hydrate for versions with SQL-null `mba_scope` (pre-slice / pre-scope). Absence of a row still means approved. |

Editor chips (`isPartialMBA` / `partialMBASelectedLineItemIds` / `partialMBAMonthYears`) post via `buildMbaScopeForSaveBody`. Version picker labels Full vs Partial from `mba_scope`. Excel (`filterMediaItemsForMbaScope`) and billing `schedule_months` omit excluded lines.
