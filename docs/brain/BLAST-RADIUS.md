## The five highest-consequence contracts

### 1. `bursts_json` shape — `lib/mediaplan/serializeBurstsJson.ts` + `formatBurstsForPersist.ts`
Changing a key or type breaks, simultaneously: pacing (`lib/pacing/burst/parseBursts.ts` → all 5 live-line-item resolvers), delivery compute (social/programmatic/search), billing (`generateBillingLineItems`, `seedLineFees`, `assertPersistedLineFeesMatchBilling`), finance (`computeCampaignFinancials`), dashboard gantt/charts (`normalizeLineItem`), the Snowflake snapshot sync (`fetchAllLineItems`), Excel/AA exports.
**Trap:** `mediaAmount` in the JSON is sourced from `deliveryMediaAmount`, so it is non-zero when `clientPaysForMedia` is true. `fee` history: see INVARIANTS (bursts contract).

### 2. `line_item_id` — `lib/mediaplan/lineItemIds.ts` (`MEDIA_TYPE_ID_CODES`, `buildLineItemId`)
The join key for: KPI fan-out (28 refs in `lib/kpi/fanOut.ts`), billing burst resolution, creative/trafficking pickers, Snowflake dedupe key, search-suffix pacing match, orphan assignment. Legacy `ML` codes still live in the warehouse after the May 2026 ML→DD/IT/PV/PB/PA/PO/OH split — matchers must handle both. Editor add and duplicate call `nextLineNumber` (`lib/mediaplan/lineItemIds.ts`) so the new id is one past the highest suffix in that channel; `assignStableLineItemNumbers` does not renumber lines that already have a number. Expert reorder (`keepLineIdsOnReorder`) stamps `position` and leaves `line_item_id` on the line it was minted for. `reassignLineItemNumbers` is not on the reorder path. New ids also clear the plan floor (`lineIdFloor`, highest number any version used); `savePlanVersion` refuses a retired id with 409 `LINE_ITEM_ID_RETIRED`. Tests: `lib/mediaplan/__tests__/lineIdNeverReused.test.ts`, `app/api/plans/save/__tests__/retiredLineId.route.test.ts`.

### 3. Fee math — `lib/mediaplan/burstAmounts.ts::computeBurstAmounts`
**The single widest blast radius in the repo.** 4 branches (see INVARIANTS). Consumed by ~19 container `get*Bursts` + every expert grid via `expertRowFeeSplit` + `computeCampaignFinancials` → every receivable, payable, accrual row, forecast line, snapshot, and export.
Known **former** divergent re-implementations (C-7/C-8 FIXED in PC2): `generateBillingLineItems` and `computeDerivedCampaignFeeAmount` now route through `computeBurstAmounts`; agency fee drift tolerance is $0.01.

### 4. Published-version rule — `lib/mediaplan/publishedVersionGuard.ts`
7 external call sites (channel GETs, list caches, dashboard client/finance/shared, MBA route, staged-version reaper). Getting it wrong makes **staged, unpublished versions visible as live plans** across dashboards, finance, and every channel read. **Published cut** = `published_version_id` AND `published_at` set (`publishedVersionIdFromMaster`; SQL `PUBLISHED_VERSION_JOIN_SQL`). Stamp predicate is canonical `isVersionPublished` — do not re-derive. Raw pointer (may be unstamped) is `publishedVersionPointerIdFromMaster`. Staging watermark `publishedVersionFromMaster` is `master.version_number` (reap/list caps only). Never `max(versions)`. Finance sections SQL (summary, cut, costs, client-pays, cut AR, dashboard monthly spend, `probeFinanceScheduleDiffs`) interpolates the fragment. Do not ship that reader change before 0070 — today it would drop the 12 C-113 plans (~$609k). After 0070 the two predicates agree and those totals must not move. `relevantPlanVersions` is still the watermark family.

### 5. Pacing maths — `lib/pacing/maths/index.ts`
Status ladder order deliberately mirrors Snowflake `V_LINE_ITEM_PACING` (`// Order from V_LINE_ITEM_PACING — DO NOT REORDER`). Band numbers live only in `PACING_STATUS_THRESHOLDS` (`lib/pacing/status.ts`): behind below 90% of expected, on track 90–110, ahead above 110 and below 115, over-pacing at 115. Changing a band changes: all spend-channel composers, the ops digest email bands, Overview tiles, AVA's narrative. The captured CASE is `sql/snowflake/pacing/16_capture_v_line_item_pacing_pre_retirement.sql` (not under `sql/snowflake/mart`). The live view changes only when that SQL is run. No app route selects the status column. `deliveryStatusFromPct` reads the same table and maps ≥115 to Ahead. Do not reorder the enum. Do not put a second number in a component.
