# Module: KPI

Three-tier KPI target resolution — publisher benchmark → client override → campaign-saved — fanned out to line-item grain, persisted to Xano (`publisher_kpi`, `client_kpi`, `campaign_kpi`), and consumed by the media-plan editor's KPI modal plus every delivery/pacing adapter (target curves, status colours).

## Key files

- `lib/kpi/types.ts` — canonical shapes + zod bodies. **`ResolvedKPIRow` and `deliveryTargets.ts::KPITargetValues` are frozen public API** (41 importing files).
- `lib/kpi/resolve.ts` — the tier-merge engine (in-memory; does not fetch).
- `lib/kpi/fanOut.ts` — group → per-line expansion via `lib/mediaplan/lineItemIds` (28 refs; ships `FANOUT_LINE_ITEM_MAP_ALIASES` to bridge the app's 4 channel-key conventions). Campaign writes always set `cpv: null`, `target_source: "target"`, `benchmark_ref: null` so a publish overwrite replaces a benchmark row.
- `scripts/kpi/backfill-benchmarks.mjs` — industry-benchmark fill for published `live`/`booked`/`approved` plans. Empty/all-zero `campaign_kpi` rows UPDATE; missing rows INSERT; any non-zero CTR/CVR/VTR/frequency is left alone. Never writes `cpv`. Requires 0080 `target_source` / `benchmark_ref`. Fail-closes if twins exist for a plan it is about to touch (apply 0083 first). Dry-run unless `--apply`. Meta/TikTok conversion rate is `0.005`. Tests: `npm run test:kpi-backfill`.
- `lib/kpi/grouping.ts` — groups plan `LineItem`s by (publisher, platform, bidStrategy, buyType, creative).
- `lib/kpi/deliveryTargetCurve.ts` — burst-aware target curve; the contract behind every delivery chart's target line.
- `lib/kpi/lineItemKpiTargets.ts` — cpm/cpv rate targets derived from bursts at render time (not stored).
- `lib/kpi/percentUnits.ts` — **sole** percent-points ↔ decimal conversion (AV-25 v2); `normaliseRatioTarget.ts` + `metrics.ts` + pacing `formatKpi` / `kpiCellColor` import it. `publisherKpiDefaults.ts` null-unset defaults. Scan: `npm run scan:kpi-percent-units` (read-only both stores).
- `lib/kpi/kpiReview.ts` — campaign MBA per-channel KPI review (`buildKpiReview({ groups, lineItemTargets })`). Groups are the same channel-platform buckets `channelCoverage` produces (Social · Meta, Prog Video · Channel Factory, BVOD), now carrying `planByLineId` (buy type, budget-weighted `buyAmount`, planned views/impressions/clicks). Entered metrics stay at line grain — shared value, else planned-spend weighted; never averaged across channels. CPV is not an entered target: leftover `campaign_kpi.cpv` is ignored. Per-line plan rate is (a) CPV-bought `buyAmount` (“plan rate”), (b) planned spend ÷ planned views (“plan rate, derived”), or (c) planned spend ÷ (planned impressions × saved/benchmark VTR) (“plan rate, derived from VTR target”); otherwise the row reads “Not a view buy” with no pill. CPM plan rate is planned spend ÷ planned impressions × 1000; CPC is CPC-bought `buyAmount` else planned spend ÷ planned clicks, else “No click basis”. A set CTR/CVR/VTR/frequency carries `targetSource` `target` or `benchmark` (`benchmark_ref` on hover). 0/null is "No target set" at the row — it does not inherit `publisher_kpi`. When every row on a card is unset (and CPV has no plan rate), the card is `noTargets` and the UI replaces the rows: admin “No KPI targets saved for {channel}. Set targets on the media plan →” (`/mediaplans/mba/{mba}/edit#builder-section-kpis`); client “KPI targets pending.” Mixed cards still grey omitted metrics for admins and hide them from clients. `shouldShowKpiReview` hides the section from clients unless a card has a saved, benchmark, or CPV plan-rate target; admins always see it when groups exist. Delivered: CTR = clicks/impressions, conversion_rate = results/clicks, CPV = card spend / reported views (BVOD completes, YouTube / Channel Factory views, Meta ThruPlays, direct video completes via `VIDEO_3S_VIEWS`; spend is the same actual/reported figure the channel card uses; no views → “Not tracked for this source”; modelled tag when the card is modelled). VTR = completes/impressions only where COMPLETED_VIEWS exists (Channel Factory partner file — PACING_FACT dual-writes it into VIDEO_3S_VIEWS; CM360 and Meta → "Not tracked for this source"). Frequency → "Not tracked yet" (C-134). CPV/VTR/CTR are never gated on buy type. Status via `deliveryStatusFromPct` (higher-is-better for CTR/CVR/VTR; lower-is-better for CPV/CPM/CPC). Mount: `components/dashboard/campaign/KpiReview.tsx`. Tests: `npm run test:kpi-review`.
- `lib/kpi/kpiBandTargets.ts` — channel accordion KPI-band overlay. Adapters keep delivered tile values; `applyKpiBandTargets` / `applyKpiBandTargetsFromPlan` attach the second line (target + caption + pill) from the same exported review resolvers. CTR/CVR/VTR captions are “plan target” or “industry benchmark”; no saved target is “No target saved” (admin) / “Target pending” (client) with no pill. CPA is left unchanged. Tests: `lib/kpi/__tests__/kpiBandTargets.test.ts` (same `test:kpi-review` script).
- `lib/kpi/kpiPacing.ts` — **retired B1-1** campaign KPI pacing rows. Unmounted from the campaign page (replaced by `kpiReview.ts`). File and tests retained pending deletion (C-135). Do not remount.
- `lib/data/readKpi.ts` — Phase 2 read choke point (`DATA_BACKEND_KPI` / `DATA_BACKEND`); shadow diffs use money cents for `cpv` and rate epsilon `1e-6` for ctr/vtr/conversion_rate/frequency. Writes remain on Xano until T4. Route-handler wrappers (`lib/kpi/{client,campaign,publisher}Kpi.ts` GETs) statically import `readKpi` — no `webpackIgnore` swallow.
- `lib/kpi/kpiWriteHandlers.ts` — admin write matrix (POST/PATCH/DELETE + campaign sync): named validation codes (`KPI_INVALID_JSON` / `KPI_INVALID_ID` / `KPI_VALIDATION_FAILED` → 400); upstream miss → `KPI_UPSTREAM_FAILED` (502). Routes are thin auth + this module. Tests: `npm run test:kpi-writes`.
- `lib/data/writeKpi.ts` — **campaign_kpi / client_kpi PG-first writes + Xano mirror** (X5 / C-18 close); `percentUnits` decimal ≤1 enforced on write (no magnitude heuristic). Campaign create/sync upserts on `(lower(mba_number), version_number, lower(line_item_id))` (newest twin wins; extras deleted). Unique index is 0083 AUTHOR ONLY. Publisher KPI writes remain Xano until a follow-up. Tests: `npm run test:write-kpi`.
- `app/api/kpis/{campaign,campaign/sync,client,publisher}` — CRUD; campaign GET uses `checkClientMbaAccess`; client/publisher GET and all writes (`POST`/`PATCH`/`DELETE` + `campaign/sync` POST) are `requireRole(["admin"])` (SEC-6 FIXED). Campaign/client mutate via `writeKpi`; publisher still Xano.
- `lib/kpi/kpiWorkbook.ts` — client-side standalone Campaign KPIs workbook (`buildKpiWorkbookBlob` + `toKpiSheetRows`). Sheet columns are CTR / VTR / Conv Rate / Frequency (no CPV). `KPISection` Download KPIs and both create/edit zip-all paths use it; media-plan xlsx append uses the same row mapping. No plan save, no KPI write, no network. Tests: `npm run test:kpi-writes`.
- `components/kpis/{KPIEditModal,KPISection,kpiHost}` — shared modal + the `KpiHost` contract with two persistence semantics: the media-plan host persists `campaign_kpi` immediately when the plan has an identity (create defers until the first save in session); the pacing host syncs immediately. Plan save still runs its own sync for the version it just wrote (including VP-1 increments). Campaign KPI entry columns are CTR, VTR, Conv Rate, Frequency — no CPV. `KPISection` Download KPIs is outline, disabled when `kpiRows` is empty or loading, and writes `KPIs_<campaign name>.xlsx` via `buildKpiWorkbookBlob`.
- `components/dashboard/ClientKpiSection` (+ `ClientKpiSlideOver`) — client hub KPI editor; rows nest in collapsible media-type groups via `lib/kpi/clientKpiMediaOrder.ts` (digital first). Display/grouping only — writes via `/api/kpis/client` → `writeKpi` (PG-first).

## Gotchas

- **Percent scale (AV-25 v2)**: UI is percentage points; storage is decimal. No `>=1` magnitude heuristic — `1.0` means 100%. Dual-store migration of leftover percentage-point / ambiguous `1.0` cells pending Luke (`KPI_PERCENT_UNIT_CONTRACT`). Never apply to cpv. Historical rescale artefacts under `scripts/data/kpi-best-practice/`.
- Unset returns **null, never 0**. Publisher/client/campaign create+patch schemas use nullable percent metrics with decimal ≤1 refine (C-20); explicit 0 is a real target. Client create no longer coerces empty metrics to 0.
- `publisher_colour` is hex-only (`#rgb`/`#rrggbb`); parse via `lib/publisher/publisherColour.ts` — invalid → documented fallback `null`, never a coerced plausible colour.
- **Two target maps, different keys**: `lineItemTargets` (`mba|version|line_item_id`) vs `kpiTargets` (`media_type::publisher::bid_strategy`). New channels must be added to both paths.
- Campaign MBA KPI review never averages targets across channel-platform groups. Frequency is "Not tracked yet" until SOCIAL_PACING_FACT carries reach (C-134). Channel Factory VTR uses PACING_FACT `VIDEO_3S_VIEWS` which dual-writes `COMPLETED_VIEWS` (`VW_PACING_PARTNER_FILE`). CM360 and Meta have no completed-views column.
- `matching.ts#normMediaTypeKey` exists because media-type keys differ across the app (`digitalDisplay` vs `digiDisplay`).
- Publisher KPI `publisher` field = Xano publisher ID string, not display name.
- Ad-serving precedence chain is locked — see INVARIANTS.
- `syncCampaignKpis` replace-set pre-read is Xano-only (not postgres) so write-side stays consistent until T4.
