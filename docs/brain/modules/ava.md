# Module: AVA (AI Assistant)

In-product Claude agent mounted as a floating chat widget on every page. Reads a `PageContext` snapshot published through a window-global bridge, calls ~31 server-side tools, can write back into the page (form patches, line-item loads) and generate downloadable artefacts. Claude-only; admin-only.

## Key files

- `app/api/chat-v2/route.ts` — the ONLY chat endpoint. Session → admin gate → `AVA_ENGINE=off` kill switch → `ANTHROPIC_API_KEY` check → system prompt + tool context → `runAvaAgent`. `maxDuration=60`, non-streaming. Holds `AVA_V2_APPENDIX` (per-tool usage catalogue).
- `lib/ava/agentLoop.ts` — tool-use loop; wraps tool throws as failures (never crashes a turn); optional Anthropic server web search (max 3 uses); `AVA_MAX_TOOL_ITERATIONS = 8`. `buildTools` is surface-aware via `avaToolDefinitionsForPage`: `/mediaplans/create` and `/mediaplans/mba/*/edit` omit `accept_ingest_proposal`; unknown/absent route also omits it (fail closed). Hub and other known routes keep the writer until W-3.
- `lib/ava/anthropic.ts` — singleton client + `AVA_MODEL` (`ANTHROPIC_MODEL` env). **`import "server-only"`**. Shared with non-AVA features: ad-copy, search-copy, researchClient, ingest mapping (`avaColumnMapping.server.ts`). Client Components must not import this module. Ingest mapping allowlist (`AVA_MAPPING_TARGET_DESCRIPTORS`) includes `buy_type`, typed money (`media_rate:*`, `media_amount:stated`, `charge:*`), and `reference:ignore` — a rate column and a stated-total column are different targets; `reference:ignore` means acknowledged, not imported (not unmapped). `parseToolProposals` drops anything outside that set.
- Artefacts: MI workbook, naming workbook, performance report. Issued `generate_performance_report` also fail-soft-persists discrete insights (`keyInsight`, `insights[3]`, recs) into `campaign_insights` via `lib/reports/persistPerformanceReportInsights.ts` — `execSummary` is not a row; `client_id` is resolved from `media_plan_masters` by MBA (tool scope has mba only). Staff read/write the library at `/insights` + embedded `RecentInsightsPanel` ("What we know", top 3 live, empty→null) / `QuickAddInsightForm` (`GET|POST /api/insights`, `GET|PATCH /api/insights/[id]`, admin-gated). Library list: newest-first, URL-persisted filters (client/mba/period|range/type/source/q/showSuperseded default off), GIN FTS via `to_tsvector @@ plainto_tsquery`, offset pagination, row-expand detail (markdown + supersede chain + campaign link). `components/insights/InsightListRow.tsx` is an unmounted extract of that row (page still inlines it). Human create/edit/supersede lives in `lib/insights/writeCampaignInsights.ts` — never delete; EDIT always SUPERSEDES (new `source=human` row + `superseded_by`/`superseded_at` on the original in one txn — original body never mutated, including AVA); RETYPE is the sole in-place exception (insight_type only + strip `insight_type_fallback*` confidence); RETIRE supersedes with a minimal `Retired: <reason>` human row; every write returns `{ item, mode, chain }`; cycle walk refuses A→B→A; foreign supersedes stamp `confidence` attribution. AVA reads live priors via `get_client_insights` / `get_campaign_insights` (ava_readonly GRANT in 0022) before rationale/commentary/report; `generate_performance_report` rejects unattributed near-verbatim restatement (`unattributed_prior_insight`, same JSON shape as `invented_money_figure`). Deck numeric fields stay snapshot-only.
- `lib/assistantBridge.ts` — the client↔AVA seam: `window.__AV_ASSISTANT__` `{summary, actions, pageContext}`; typed action handlers; `ava:open-chat` CustomEvent. 12 provider call sites; breakage is silent (window global).
- `lib/ava/buildAvaSystemPrompt.ts` — truncating PageContext serialiser (6,000 chars, depth 6). Create/edit ingest guidance is appended **after** `AVA_V2_APPENDIX` so it wins: `load_ingest_into_form`, form for human review, human saves — it does not describe accepting into a plan.
- `lib/ava/tools/loadIngestIntoForm.ts` — create/edit form door for a staged ingest (`confirm: true` required; writes `capturedLineItemsLoad` including `ingestStageId`). Before load: money gate (`reconciliation.accept_ok` — same `block_reason` + `delta` as Hub 409, records `ingest_runs` `blocked`) then `evaluateRequiredFieldGate` (names unmatched required fields or unresolved raw values; no run — mapping/value cards are the retry). After load, Save does not re-run either gate. Human Save on create/edit completes the stage via `POST /api/plans/save` (`completeStagedIngestAfterSave`) — not `executeIngestAccept`. Missing/expired copy matches `get_pending_ingest_review` (A5: never “expired”, never a stage id). Value cards (`ingest:value:<field>:<raw>`) offer the field's registered vocabulary; confirm calls `learnSynonym` (`0060` AUTHOR ONLY) so the same publisher+raw is not re-asked. When `pageContext.entities.enabledMediaTypes` (fetch keys: `ooh`, `radio`) is present and omits the loaded channel, the tool result says that channel will be switched on so AVA's prose matches the page. A client/MBA mismatch warns; it does not block.
- `lib/ava/applyIngestLineItemsLoad.ts` — `handleSetLineItems` on both mega-pages. If the form flag (`mp_ooh` / `mp_radio`) is off, it `setValue`s the flag dirty so the container mounts, writes the rows, marks unsaved, and scrolls to `media-section-<flag>`. Edit also writes the hydration setter (`setOohLineItems` / `setRadioLineItems`) — the same dual-write draft restore uses — because OOHContainer hydrates from fetched `oohLineItems` via `useStableHydration`, which skips an empty first paint and would otherwise wipe a media-only load. Create has no separate hydration state (`initialLineItems` is the media array); do not dual-write there. The returned note names the channel and whether it was turned on; nothing is saved.
- `lib/ava/tools/pageToolOffer.ts` — surface-aware `accept_ingest_proposal` offer (`avaToolDefinitionsForPage`). Tests import this, not `registry.ts` (registry loads every tool, including `server-only`).
- `components/ChatWidget.tsx` (~1k lines) — the UI; xlsx attach/drop POSTs `/api/admin/ingest/review` (Hub engine, staged) then confirm via `load_ingest_into_form` on create/edit (form only, human saves) or `accept_ingest_proposal` on the Hub. File-drag overlay uses `isFileDragOver` (never widget-move `isDragging`): dashed `border-primary`, `bg-primary/10`, copy “Drop an .xlsx schedule to review.” Attach row includes “or drop a file here” (`text-[11px] text-foreground/70`, not `text-muted-foreground`). Invalid types still error (e.g. .pdf). The user-visible upload turn is a short sentence (`Uploaded "<file>" — can you review it?`), sent only after a local Review it / Not now card (`buildIngestProposalPrompt`; Not now leaves `pendingIngest` in place and does not cancel the stage). `IngestChatSummary` travels as `pendingIngest.summary` on POST `/api/chat-v2` (not user-turn prose). Assistant turns render sanitised markdown (`react-markdown`; GFM tables parsed in `lib/ava/chatTurnBlocks.ts`) so the confirmed ingest table is a real table; question/file cards interleave after the first table. User turns stay plain text. `get_pending_ingest_review` returns a compact confirmed markdown table plus existing `questions` cards (required/enrich field source, optional money recon, MBA) — never a second question system. Mapping cards walk unmatched required then enrich in `card_field_ids` order; each card is the AssembledView field asking which file column feeds it. A sourced controlled value that does not resolve is a separate value card (that field's vocabulary labels; a global synonym pre-selects and still requires Confirm; confirm learns the publisher synonym). Unused leftovers stay named in ignored/not_used (count line on the first turn, no card). Money cards only when `media_money` is unmatched or the 0.5% gate fails (one card). Choice/multichoice cards include Other (typed answer) and Skip (`SKIP_ANSWER`); ingest skip is Leave unmapped (decline, no remap persist, recorded in `ava_chat.answers`). Remove this mapping is the only chat delete. Required-field cards ask “Which column in this schedule holds …?” and offer Not in this file ahead of Other. Invented headers reject without recording so the card re-opens. Mapping answers that persist go through `validateRemapHeader` + `remapIngestColumn` (session email as `changedBy`). User bubbles use `displayMiAnswerText` so skip shows as Skipped. Operator ingest directives live in `lib/ava/skills/skillGuidance.ts` only. User-facing ingest copy follows [AVA-VOICE.md](../AVA-VOICE.md): tool results are user-ready; a missing row never says expired and never includes the stage id; expired may name the 24-hour hold. `meta.ingestStageMissing` flips the footer chip to Attach the file again. `/api/processPlan` autopopulate remains for the assembled-media-plan-autopopulate skill; standalone `/admin/schedule-ingest` is still mounted.
- `lib/ava/skills/registry.ts` + `skills/content/**` — vendored Assembled skill markdown, read from disk via `process.cwd()` at request time (bundling/tracing changes break at runtime only). 24k-char injection budget; marketing-brain decision-rules auto-chained.
- `lib/ava/autopopulate/**` — media-owner xlsx → plan parse (exceljs + Claude mapping) with in-memory rate limit.
- `src/ava/{systemPrompt,voiceSpec,modes}.ts` — identity/boundaries/voice primitives (historical `src/` location, same `@/` alias).

## Depends on

Nearly everything (read tools): media-containers API, pacing caches + maths, delivery snapshot, finance xanoReferenceCache, clients cache, naming templates/compose, creative assets (PG via `xanoCreativeAssets`), planning audiences (PG via `xanoPlanningAudiences`) + meta, specs, RBAC. Campaign summary helpers in `lib/xano/ava.ts` read masters/versions from Postgres. `save_client_brain` writes via `updateClientPostgresFirst` (Xano mirror best-effort). Postgres plan/finance/xero reads go through `db/avaClient.ts` (`AVA_DATABASE_URL` only) when configured.

## Consumed by

`lib/ava/types.ts` (`PageContext`, `FormPatch`) is imported by 13+ files OUTSIDE AVA — trafficking, creative, dashboards, finance overview panel, planning, both mega-pages. Changing `PageContext` touches most page shells.

## Gotchas

- Create `getPageContext` publishes `entities.mediaTypes` as labels and `entities.enabledMediaTypes` as fetch keys (`ooh`, `radio`, … from `mediaKeyMap`) so `load_ingest_into_form` can compare case-insensitively to the tool channel. Omit `enabledMediaTypes` when none are on — the tool then does not claim a switch-on. Edit already publishes fetch keys.
- Edit ingest load must dual-write hydration + media setters. `useStableHydration` (`hooks/useStableHydration.ts`) skips `length === 0 && lastHydratedRef.current == null`, then `handleOohMediaLineItemsChange` always `setIfChanged`s media state — a media-only load into an unmounted OOH container is wiped on first hydrate from empty `oohLineItems`.
- `attachments`/`questions` are display-only — never round-trip into Anthropic message history (corrupts turns).
- Assistant turns go through `react-markdown` (already in the tree; no `rehype-raw`, no extra markdown lib). GFM tables are split in `lib/ava/chatTurnBlocks.ts` and horizontally scrolled inside the turn. User turns stay `whitespace-pre-line` plain text.
- `deriveAvaIdentifiers` regex-parses the route string for slug/MBA — adding a reserved first segment under `/dashboard/*` mis-derives clientSlug.
- MI SPECS mapping (`lib/specs/resolve.ts`, `buildMiWorkbook.ts`) fills template columns from existing publisher JSON keys only — aliases include File Format ↔ File Type and Physical Dimensions; `joinScalar` renders objects as `key: value` lines; Civic Outdoor uses the site catalogue + `universal_specs` (no `formats[]`). Roles live in `lib/specs/templateRegistry.ts` (required = fills-today). Never edit vendored `lib/specs/mi-library/`. Cover **Overall Supply Deadline** and SPECS **Supply Deadline** dates are derivations from structured min/max/business columns (`deriveMaterialDeadlines.ts`); prose-only publishers contribute nothing. The `publisher_specs` store (`0041`, applied) is the join + JSON home; deadline reads prefer those min/max/business columns and fall back to the vendored parse when the row is missing or columns are NULL (`0046` AUTHOR ONLY). HTTP material-instructions and AVA MI tools refuse silent MBA-wide; version-scoped answers persist on `media_plan_versions.mi_resolution` (`0044`, applied).
- `lib/avaSnowflake.ts` is dead (zero importers). `lib/codex/**` is the Tasks domain, not AVA.
- Rate limiters are in-process Maps — per-instance only on serverless. Staged ingest lives in `ingest_stages` (0050 AUTHOR ONLY) with a 24h TTL; overlay until the migration is applied. User-facing ingest copy follows [AVA-VOICE.md](../AVA-VOICE.md); missing never says expired and never prints the stage id.
- Skill markdown edits: content lives in-repo (`lib/ava/skills/content/`), vendored from the Assembled skills — keep in sync deliberately, not ad hoc.
- Postgres reads for AVA use `AVA_DATABASE_URL` as role `ava_readonly` (`db/migrations/0003_ava_readonly.sql`: explicit SELECT allowlist + `ava_read` RLS policies, `statement_timeout=5s`, `default_transaction_read_only=on`). Never the owner/`DATABASE_URL` connection.
- **`client_notes` stays on the AVA allowlist (Q22)** — deliberate; Stage 3 populated notes are chat-queryable. New Codex tables from 0013 are not granted to AVA. See `docs/brain/modules/codex.md`.
- AVA tool `fy` is the Australian FY **ending** year via shared `lib/ava/tools/fyToRange.ts` (`fy=2026` → Jul 2025–Jun 2026). Distinct from finance hub `fyMonthRange` (start-year). Responses that apply an fy filter echo `range` (e.g. `"2025-07..2026-06"`).
