# Module: Dashboards, Charts & Document Generation

## Client dashboards

- Home `/dashboard` (`DashboardOverview`): Key metrics tiles derive from the same filtered live campaign/scope arrays as the panels (`lib/dashboard/homeDashboardFilters.ts`). Live scopes use `isLiveScopeStatus` (Approved / In-Progress, case/hyphen/space tolerant) — no end-date bound (scopes lack one). Live-client KPI union keys through `normalizeClientFilterValue` so campaign/scope name drift does not inflate the count. Fourth tile **Media Spend to Date** sums `GET /api/dashboard/planned-to-date?fy=` `byMba` over `filteredLiveCampaigns` (`sumPlannedToDateForCampaigns`); join keys are `mbaJoinKey` (trim + lowercase) on both sides; displayed `mp_mba_number` stays as stored; missing keys contribute 0; duplicate campaign rows that differ only by MBA case count once; no client-side clamp or pro-rata. Compact display is `formatMoneyCompact(n, { millionScale: "home-spend" })`; tooltip is exact AUD + “Planned media, published versions, to {d MMM yyyy}” (Melbourne). Fetch in flight → skeleton (never a money zero); fetch error → omit the tile (`console.error`); AVA `counts.metrics` matches the visible tiles. Not `mp_campaignbudget`, not delivered actuals. Campaign client names come from `GET /api/media_plans` → `mediaPlanVersionsCache` (postgres overlays master `mp_client_name` via `overlayMasterOwnedListFields` — DI-9b). Page identity stays in `MediaPlanEditorHero` (CTA only); search/client/saved-view controls live in `DashboardFilterBar` below the hero. `/mediaplans` reuses the same filter bar + pin storage (`lib/dashboard/savedDashboardViews.ts`, key `dashboard:savedViews:v2:${userId}`) with Home’s hero→filter→FY/Layout rhythm and **no** key-metrics strip (BUX-4). AU FY overlap filter (`lib/dates/auFinancialYear.ts`, `?fy=` start-year / `all`; default current) is client-side on Home campaign cards and `/mediaplans` — reuses `australianFyStartYearForDate` from `lib/finance/months.ts` (not AVA ending-year `fyToRange`). Shared hero row uses content-floor wrap (`basis min(280|460|780px,100%)` + `shrink-0`; `actionsFloor` `default` vs `toolbar`) so CTAs cannot squeeze/clip under `PageHeroShell` `overflow-hidden` when the sidebar collapses. Filters update tiles and panel badges together; "Clear filters" clears the active filter only and does not wipe saved client pins. "Save selected clients" upserts a `Pinned clients` saved view (restore source on load); the legacy `clientFilters` key is write-through only. Campaign media-type pills on Home table+cards are `MediaChannelTag` from `campaignMediaTypeTagLabels` (registry labels — same helper as `/mediaplans`). Row dates use `lib/dashboard/safeFormatDate.ts` so one blank/malformed date cannot blank the page. Heading outline: `PanelRow` section titles are `h2`; nested `PanelTitle` panels under Campaigns & scope use `as="h3"` (default `PanelTitle` is `h2`, `CardTitle` is `h3`). Campaign table/card actions are `CampaignRowActions`: menu-only Open + Download pair, stacked in tables (`layout="stacked"`, pair `min-w-[10rem] w-full`, both controls span the unsized Actions cell), two columns on cards (`layout="columns"`, each control fills its column), menus open downward only (`menuSide="bottom"`, `avoidCollisions={false}`). Home live/due-soon/finished tables pin non-action columns to the same widths as `/mediaplans` (client `w-32`, campaign `w-40`, MBA `w-24`, dates `w-24`, budget `w-24`, version `w-20`, status `w-24`, media types `w-48`) so leftover width under `table-layout: auto` lands on Actions (header left-aligned). Cards are unchanged. Open is never disabled — Edit media plan · vN is first when `canEdit`; View campaign is always present (disabled + “No client dashboard” when slug is empty). Edit is omitted when `canEdit` is false. Download menu still lazy-fetches `GET /api/mediaplans/mba/[mba]/documents` (cached per MBA) and streams files via version download.
- Routes: `app/dashboard/[slug]/**` (tenant-scoped client views) + `components/dashboard/**` (57 files: hero KPI bar, spending insights, campaign viz, delivery sections, slide-overs).

### Campaign MBA layout

`CampaignPageAssembly` (`app/dashboard/[slug]/[mba_number]/components/CampaignPageAssembly.tsx`) is the compositor. Sole production mount: `app/dashboard/[slug]/[mba_number]/page.tsx`. Section order:

1. Hero
2. Planned audience
3. **Where we are** (`CampaignStatusStrip`)
4. **Channels at a glance** (`ChannelsAtAGlance`) — omitted when `visibleCoverageCards` is empty (no cards, including a campaign with no delivery)
5. Admin-only: Team hours (`CampaignHoursWidget`, `GET /api/codex/time/summary`) → **KPI review** (`KpiReview`, `lib/kpi/kpiReview.ts`, clients and admins; hidden when no review cards) → Recent insights
6. Delivery (`CampaignDeliverySection` accordion)
7. Media plan (`MediaPlanVizSection`)
8. **The plan** (`SpendChartsRow`)

Hidden `CampaignDeliverySection showAccordion={false}` still mounts so one `/api/pacing/bulk` (`onCoverage` + `onKpiReviewGroups`) can feed glance + strip + review. `kpiTargets` is `useMemo`d on `savedCampaignKPIs` (same contract as `lineItemTargets`); `handleCoverage` skips `setCoverage` when `coverageEntriesIdentityKey` is unchanged so a new coverage array cannot loop the page. Media plan Summary must not show a second media-mix chart. Client details modal never links clients to `/mediaplans/.../edit`. Live-now freshness is delivered `asOf`, never a hardcoded "ago". Hours, insights, and Media plan Weekly/Monthly + Download PNG are admin-only (`isAdmin`); clients never see them. KPI review is visible to clients and admins. `GET|POST /api/mediaplans/mba/[mba_number]/material-deadlines` is tenant-scoped (POST also admin); `MaterialDeadlinesStrip` is unmounted.

**CampaignStatusStrip** replaces the old Progress summary / `CampaignSummaryRow` verdict line (`CampaignSummaryRow` stays in the tree for helper tests; not mounted). Left: status pill + `statusSentence`. Right: Delivered to date / Expected by now / Impressions / Time elapsed. Pill is `computePacing` → `pacingStatus()` via `campaignPacingVerdict`. Delivered to date is "—" when `actualSpend` is unset (impressions-only, same gate as `page.tsx` `hasReportedDeliveredSpend`). **Impressions hide when `hasDelivery` is false.** Coverage (`lib/delivery/channelCoverage.ts`) supplies `channelsReporting` / `channelsTotal` / ahead-channel into the strip; planned deliverables are summed from each group's section `progressCards` "Delivered X · Planned Y" (not the raw line `impressions` field — CPV planned views live there). Direct-digital groups (`digital-display` / `digital-video` / `digital-audio` / `bvod`) read the impressions card at `progressCards[0]` (CM360 clicks sit at `[1]` — that 100 is not delivered impressions). Other families still read the deliverable card at `[1]`. When matching line ids exist, delivered and planned impressions sum those line captions. The strip caption is delivered / that sum. Glance noun stays Impressions unless every card in the group is CPV, then Views.

**`statusSentence`** (`lib/dashboard/statusSentence.ts`) — first match of a–d, with an unknown-spend gate after **a**:

- **a.** `channelsTotal` known, `channelsReporting < channelsTotal`, and `spendPct < 0.5` → "{n} of {total} channels are reporting so far, which is why delivered spend looks low." If `aheadChannelName` is set (first reporting channel whose glance card status is ahead — spend, or deliverable when spend is hidden), append " {Name} is ahead." Omit the clause when none are ahead on that measure.
- **unknown spend.** When `actualSpend` is unset, skip b–d and return "No delivery reported yet." Never treat missing spend as $0 in the behind-by-$X gap.
- **b.** `impressionsPct > spendPct + 0.15` and actual CPM below planned → cheaper-than-planned sentence.
- **c.** behind / over-pacing / critical → "Spend is behind the plan by {gap}. See the channel cards below for where."
- **d.** "Delivery is on track against the plan."

Strip "Day N of M" uses Melbourne civil-calendar inclusive counts (`inclusiveCampaignDayMetrics` / `getMelbourneTodayISO`) — not the host timezone wall clock. `getDeliveredTotalsForCampaign` does not swallow `loadDeliverySnapshot` failures (logs `[getDeliveredTotalsForCampaign] loadDeliverySnapshot failed` and rethrows); the campaign page catch logs `[campaign-page] delivered totals failed` and leaves `actualSpend` unset. Fixed-cost `fetchDirectPacingRows` still degrades to `[]` after a source log. Campaign-page snapshot Snowflake exec labels are `delivered-totals_social` / `delivered-totals_non_social` / `delivered-totals` (overlay); CSR bulk stays `pacing_bulk_*`. `DEFAULT_EXECUTE_TIMEOUT_MS` is 30s in production (was 8s — C-133). Overlay `queryDailyFacts` runs in parallel with PACING_FACT, and overlay failures `console.error` without failing the snapshot.

**Coverage statuses** (`ChannelCoverageStatus`): `reporting` (≥1 PACING_FACT / chart daily row) · `connecting` (a delivery source exists — `delivery_source_map` row or social classifier — but no fact rows yet, and the earliest burst is not after Melbourne today) · `not_started` (source exists, earliest burst after today) · `no_source` (no map row / classifier). Direct-digital groups are not Connecting just because they sit in a digital bucket — without a map row and without CM360 rows they are `no_source` and stay in Awaiting delivery. Sort: reporting → connecting → not_started, then planned spend desc. **Connecting** caption is "Awaiting first report". There is no source for a first-report-expected date (C-131). `not_started` caption is "Starts {date}". **`no_source` is excluded from glance** (`visibleCoverageCards`) and stays in Awaiting delivery. Glance is a 4/2/1 card grid; spend follows ZERO-$ LAW (modelled flag when `derive_spend_from_plan`; `fixedCostMedia` overlay from REPORTED_SPEND).

**Null-KPI convention:** delivery KPI tiles print what they are given. `summarizeActuals` / `summarizeDv360Actuals` return `null` (not 0) for a ratio whose denominator is 0 in the window (cpm/ctr/cvr with no impressions, cpc with no clicks, cost_per_result/cpa with no results). `KpiTile` renders a dashed empty tile — "Not tracked on this campaign" for CVR/CPA, "None recorded" for CTR/CPC/CPM. CPM caption `planned ${cpm}` only when every line in the group shares one plan CPM; View rate caption is `N% of impressions`.

Client-facing gantt sideline labels (`buildGanttSidelineLabel`) are `{publisher} • {creative_targeting → site ≠ left → placement → daypart → Line item id}` — bid strategy is not used on the sideline. Sideline wrap is `wrapGanttLabel` (44 chars × 2 lines at `padL` 360); hover `<title>` + tooltip keep the full string. Bar text for a line whose first burst starts after Melbourne today is `Starts {d MMM}` (`mediaGanttReshape`); delivered-in-bar is not in the gantt tree (C-130).

## Chart system

- `lib/charts/registry.ts` — `MEDIA_TYPE_REGISTRY`, THE media-type chart colour/label source, mirroring `mediaTypeTheme` in `lib/utils` (two overlapping colour sources — keep in sync). `line_channel` spellings `digi_*` / `integrations` / `social` alias onto registry keys. - `lib/charts/theme.ts` — Recharts plumbing: Tailwind arbitrary selectors keyed on Recharts' literal default strokes (`#ccc`/`#fff`) — **a Recharts upgrade that changes those defaults silently un-styles every chart**.

## Document / export generation

Three stacks — know which one you're in:
1. **exceljs** workbooks: `lib/generateMediaPlan.ts` (2.3k lines — also the `LineItem`/`MediaItems` **type hub with 32 importers**; renaming a field cascades to all 20 containers + KPI grouping + Excel). Buy Type cells use `formatBuyTypeForExport` / `BUY_TYPE_UI_LABELS` (`lib/mediaplan/buyTypeLabels.ts`) — planner combobox strings, `package_inclusions` = Package Inclusions. OOH client explode and persisted `explodeExcelLineItems` both take Buy Type from the **line** (`excelBuyTypeFromLine`); `addKPISheet` formats the same way. Finance exports (7 modules), naming/trafficking workbooks, MI spec workbook. Editor Excel stays client-side; `POST /api/mediaplans/generate-pdf` is locked (admin/manager, `{mba_number,version_number}` only) and returns stored file metadata — no client totals. 422 unless `isVersionPublished` (`published_at`); copy is `unpublishedDocumentError` (no `campaign_status`). The leftover `isDownloadableCampaignStatus` (everything except draft) stays exported and unused by this gate.
2. **jsPDF**: `generateMBA.ts` (PC3: footer `v{n} · {hash8}` from `snapshot_checksum`; optional second arg `creationDate?: Date` calls `doc.setCreationDate` — the variable `putInfo` writes as `/CreationDate`. Omitted keeps the constructor's `new Date()`. `setProperties` does not reach that field (documentProperties is title/subject/author/keywords/creator only). `/ID` is already stable via the post-output hash. `/api/mba/generate` renders from `schedule_months` + `approved_slice` + `mba_fee_snapshots`, deriving the slice from billing `schedule_months` at read time when none was frozen — never writes `approved_slice`; optional `selectedMonthYears` / `approvedLineItemIds` overlay the PDF only (`X-Slice-Source: live`); optional `liveCampaignDates` prints form campaign dates without setting `liveOverlay`; checksum stays frozen; extra keys 400 `CLIENT_TOTALS_REJECTED`; `X-Slice-Source` header for support; `requireRole(admin)`, body `{mba_number,version_number}` plus those optional keys, 422 unless `isVersionPublished` — not approved-or-beyond; partial MBA adds one `Scope:` line + `_partial` filename, full MBA PDF bytes unchanged unless live dates change the Campaign Dates line), `generateScopeOfWork.ts`, `generateBillingSchedulePDF.ts`.
3. **PPTX ×2 incompatible approaches**: pptx-automizer (`lib/planning/export/buildPlannerDeck.ts` — never starts from blank; hardcoded placeholder geometry) vs raw JSZip token substitution (`lib/reports/buildPerformanceReport.ts` — fixed-arity payload; adding a 5th channel/KPI means changing template + token map + tuple types + AVA tool together; `escapeXmlText` must escape `&` first).
4. **B3-1 campaign report:** `POST /api/campaigns/export-report` (admin + rate limit) → `assembleCampaignReportData` + `buildCampaignReportDeck` on the same Assembled root/template as export-deck. While a working draft or dirty form exists, **client** document downloads and pacing keep serving the **published tip**. Planner draft downloads are a separate `POST /api/mediaplans/draft-documents` (stamped DRAFT, writes nothing) and do not replace that tip. `DOWNLOAD_BLOCKED_MESSAGE` is the unpublished stored-file wording; leftover `isDownloadableCampaignStatus` stays unused. `/api/mba/generate` still requires `isVersionPublished`. ## Excel/export gotchas (verified, recurring)

- Excel Column N "Gross Media" contains **net** (C-1); no per-line fee column; export reads `calculateAssembledFee()` totals verbatim, never recomputes per line.
- OOH Buy Type on Excel is the **line** (`excelBuyTypeFromLine`); do not read `bursts[].buyType` (stamped `"bonus"` for inclusions).
- `groupLineItems` substitutes `deliverablesAmount` when `grossMedia === 0` — inflates section totals for client-pays lines.
- Partial-MBA: export must read `partialMBAValues` (see INVARIANTS fee section).
- exceljs is imported client-side in the mega-pages and finance dialogs (bundle cost); `file-saver` static in several finance components.
