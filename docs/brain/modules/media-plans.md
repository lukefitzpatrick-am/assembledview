# Module: Media Plans

The campaign builder. Creates an MBA-numbered plan (`media_plan_master`), cuts immutable version rows (`media_plan_versions`) per save, and writes per-channel line items into 20 Xano tables (`media_plan_television` … `media_plan_influencers`), each row carrying a `bursts_json` array. Generates the MBA PDF + media plan Excel and uploads them to the version row.

**Versioning rule:** A campaign has at most one unpublished draft version at a time. Saving overwrites that draft, whatever number it carries. Publishing freezes it. The next edit after a publish creates the next number as a fresh draft. Editing any older version cuts the next number from its content. **Transitional:** until the draft-collapse migration runs, editing an older version of a campaign that already has an unpublished newest version produces a SECOND unpublished draft. Accepted, not silent. Collapse of old drafts is a separate post-merge data migration — not this resolver. **Interim:** while `SAVE_PUBLISHES_IMMEDIATELY` is on, Save publishes every cut — there is no unpublished overwrite and no working-draft save path. Retraining: the edit bar primary is **Publish** (stays on the campaign and downloads the media plan); **Publish and exit** is the caret item (no download). Create still labels Save and navigates to Campaigns after the first successful mint. There is no second publish step.

## Save protocol (verified)

**Xano path (explicit `WRITE_BACKEND=xano`):**

1. Compute `approvalSelectionFingerprint`; approval-set change → `forceIncrement`.
2. `PUT` with `deferMasterVersionPublish: true` → server: reap staged orphans → `nextMbaVersionNumber` → `recomputeAndValidateBillingScheduleOnSave` (authoritative; 409 on $0.01 divergence) → POST new version row (or PATCH in place while `status === "draft"` && !forceIncrement).
3. ~20 conditional per-channel `save*LineItems` writes. Any failure → abort, master NOT advanced.
4. Docs generated + uploaded in parallel. **Unpublished versions:** MBA PDF + Media Plan file steps are marked `skipped` with “Documents generate from published versions” (`lib/docs/saveDocSteps.ts`); SavingModal does not enter “Saving with Errors” for skips alone. `/api/mba/generate` gates on `isVersionPublished` (`published_at`). Missing `approved_slice` is derived from billing `schedule_months` at render time (never written back). Optional live Partial MBA keys overlay that PDF only (`mbaRenderFilters.ts`); they never mutate `approved_slice`. Optional `liveCampaignDates` is independent of that overlay (full MBA may send it; `deriveLiveMbaScopeSelection` stays null). Create still POSTs `{mba_number,version_number}` only. Edit Generate MBA and Save-and-download-all POST live overlay keys from `deriveLiveMbaScopeSelection` (`liveScope: true`) only while Partial MBA is on, plus `liveCampaignDates` from the form (`mp_campaigndates_start` / `_end`) when Melbourne-normalised dates differ from the loaded version row; a full MBA stays identifiers-only for overlay so generate does not re-sum totals. Save-time document upload stays identifiers-only so it renders the frozen post-save slice (no live dates). Versions with no schedule rows skip with “No billing schedule persisted” (`isExpectedDocGateSkipError`), not a red save failure. Real doc failures on published versions remain `error`.
5. `PATCH` publish (advance `master.version_number`). Failure → Retry-publish button. Xano has no multi-table transactions — stage-then-publish is the closest contract; abandoned failures leave staged rows until the next save reaps them.

**Postgres path (`WRITE_BACKEND=postgres`, default, T4c wired):** `POST /api/plans/save` → `savePlanVersion` then, when `XANO_MIRROR_ENABLED=true`, best-effort `mirrorPlanToXano` — the mirror is **off by default** (post-cutover MBAs have no Xano master row). Disabled saves skip the client-name lookup and return `{ mirror: "disabled", mirrorDurationMs: 0 }` (fields still present). After the version commits, optional `ingestStageId` runs `completeStagedIngestAfterSave` (`insertIngestPanels` keyed by `attrs.ingest_source_row_refs` / `source_row_ref` — never last-N position — then `ingest_runs` accepted + `retainIngestStage`). A missing/expired stage never fails the save. Panel insert failure, empty remap, and written-vs-surviving-ingest-panel-count mismatch are named on the 200 (`ingestPanelError`) and do not roll back the version; the stage id is kept so Save can retry. `uq_line_item_panels_line_source` (`0055`, applied) rejects duplicate ingest `(line_item_id, source_row_ref)` rows. `ingest_runs` and retain fail open. Idempotent when `retained_at` is already set. `savePlanVersion` / `SavePlanVersionInput` / `mirrorToXano` / working-draft PUT stay unchanged. Draft updates `(master_id, version_number)` in place; `new_version`/`publish` insert at server-resolved tip+1 (O4.6; client `versionNumber` ignored for those modes); line ids are client-stable (never regenerated); publish aborts if `count(line_items)=0` (BOSS006); mid-txn failure rolls back version + lines + schedules (PENFOLD016 kill-shot). Editor sends `masterId` from `media_plan_master_id` (not combined-payload version `id`); mismatch vs mba → 422 `MASTER_ID_MISMATCH` (no silent remap). Commercial status does **not** ride the save payload onto the version (CS-B) — `PATCH …/status` writes the master; new version INSERTs snapshot the then-current master status. 23505 on versions UNIQUE → `VERSION_ALREADY_EXISTS` (not line-id dupe) — backstop only once tip is server-resolved. Mirror failure leaves Postgres intact and returns `{ mirror: "failed" }` (retry via admin). Create/edit save-status never shows a Mirror to Xano step (Save plan + KPI sync only); the UI ignores `mirror` / `mirrorError`. Publish mirror also PATCHes Xano master watermark. Deleting `mirrorPlanToXano` is X-series severance. **O4:** AUTO-line / month-header drift vs the burst `autoReference` preview does **not** pre-block save (server recomputes `schedule_months` + blob anyway); response may include `billingCorrection` for a visible toast. Explicit `billingMode=manual` + C2 sum violations still 409.
